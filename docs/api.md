# API contract

Committed machine-readable contract: openapi.json. Runtime schemas: packages/contracts/src and apps/api/src/routes.ts. The request schemas and route catalogue are generated. Auth/session, password change, account provisioning and import confirmation now have shared runtime request/response schemas. Other ancillary response schemas remain broader than their actual DTOs and are explicitly tracked as unfinished contract work. There is no documentation UI.

Base path `/v1`. Health/readiness are `/healthz` and `/readyz`. JSON operations return `{ "data": ... }`; login/session return their explicit session object. Errors always contain `{ "error": { "code": "FORBIDDEN", "message": "FORBIDDEN", "requestId": "UUID" } }`, never raw provider/database error text. Validation 400; missing/expired session 401; forbidden/CSRF 403; optimistic conflict/deadline 409; rate limit 429; missing integration/unready 503. Unknown routes return 404. Bodies are bounded to 1 MiB except raw XLSX/file uploads with 5/10 MiB limits.

POST `/auth/login`: schoolCode, loginId, password. Owner uses separate `/auth/owner-login` with the same body shape and a securely configured owner UUID; the two school/login fields are ignored for owner resolution. Successful login returns user ID/role and CSRF token, sets `__Host-papperly` Secure HttpOnly SameSite=Strict Path=/, and never returns Supabase tokens. Requests need an allowlisted Origin; mutations also need X-CSRF-Token. Use HTTPS, same-site app/API origins, and credentials: include. Cross-site cookies are deliberately unsupported. No remember-me/max-age cookie is issued; browsers may restore session cookies, so closure is not guaranteed logout. Twelve-hour absolute and thirty-minute idle limits are checked server-side; an active attempt bypasses idle expiry only within the absolute lifetime. No public signup or anonymous Auth is implemented.

POST `/auth/reauthenticate` accepts password. POST `/auth/password` accepts userId/currentPassword/reason and optional newPassword for self-change only. Staff resets generate a fresh password and return it once. Sessions are revoked before Auth update, so an Auth failure leaves access revoked and requires retry/recovery. Self-change issues a fresh application session and CSRF token after revoking prior sessions. `/auth/logout` invalidates the application session and clears the cookie. Login ID changes use `/accounts/login-id`; historical IDs remain reserved. Approved student-only ASCII folding is versioned and applied consistently; staff casing remains significant.

After refresh, `/auth/session` restores the session CSRF token without exposing provider tokens. Do not persist provider tokens or passwords. During active attempts, clear local answer state on logout; only server acknowledgement means saved.

Common reads use GET `/exams`, `/questions`, `/attempts`, `/answers`, `/results`, `/groups`, `/posts`, `/queries`, `/query-messages`, `/query-cycles`, `/notifications`, `/articles`, `/audit`, `/insights`. Limit defaults to 25, max 100; offset max 10000; deterministic primary-key order. Applicable exact UUID filters are documented in OpenAPI. No client school ID is accepted for tenant context. RLS filters every returned row, including direct PostgREST reads. No raw table-write endpoint exists.

Core workflow:

1. Owner POST `/schools`; authorized parent POST `/accounts`. Account reservation uses identityKey and returns existing/reserved/active/conflict. Newly created Auth credentials are returned only on the creation response, never on a retry. Staff must change temporary passwords. Administrator creates `/classes`, `/assignments`; assigned teacher/admin `/students/enroll`.
2. Teacher saves `/questions/drafts`; `/questions/format` queues AI, `/jobs/status` reports pending/unavailable/failure. Raw input is retained and nothing auto-publishes. `/exams/publish` accepts classId and the complete paper schema with protected keys/rubrics. This is a new immutable version, not a patch. `/exams/cancel` rejects after any attempt starts.
3. Student POST `/attempts/start` with versionId and a newly generated per-tab writer UUID. Retain that writer UUID for refresh-equivalent resume; another writer receives WRITER_CONFLICT. GET attempt/answer records contain acknowledged state. Normal attempt reads do not expose writer tokens. `/attempts/takeover` requires attemptId, new writer UUID and current password; deadline stays unchanged.
4. `/attempts/answers`: attemptId, questionId, response, revision and writer. Each question starts at revision 1; identical retry is idempotent; only next revision advances. Stable option/item IDs are used, not display letters. Null/unanswered responses score zero. After deadline the function finalizes saved work and returns ATTEMPT_EXPIRED. `/attempts/submit` takes attemptId/writer and returns the same terminal receipt on retries. Scheduled processing is a second expiry path.
5. Teacher `/grades/details` sees protected rubric/grade records only for authorized exams. `/grades/review` supplies score/revision/feedback/reason. Marks are integer hundredths (500 means 5.00). `/results/publish` requires all final scores and creates published snapshots/revisions, notifications and insight work. AI retry never changes reviewer-approved marks. Students receive only published score/feedback DTOs; answer-key release remains disabled.
6. Groups `/groups`, `/groups/members`, `/groups/posts`, `/groups/posts/read`. Only assigned teachers write posts; no group-reply/comment/reaction API exists. Pending memberships never grant content access. Removed memberships immediately lose current private download rights.
7. `/queries/policy`, `/queries`, `/queries/replies`, `/queries/state`, `/queries/deadline` implement private routing, elapsed-hour snapshots, substantive solutions, student confirmation/clarification and deadline history. Acknowledgement does not deliver a solution. Seven days is 168 elapsed hours. `/resources/reassign` preserves query deadlines; extension is separate. Administrator sees metadata, not messages.
8. `/dashboard/student`, `/reports/student`, `/reports/statistics`, `/reports/school`, `/insights/correct` return published-only evidence/metrics and scoped guidance. No shared HTTP cache exists. `/reports/exports` queues an actor-scoped private CSV; `/exports/{id}` rechecks current scope, source version and 24-hour expiry. Missing data is null/empty, not invented zero attainment.
9. `/profiles/manage`, `/profiles/updates`, `/profiles/detail`, `/directory/search`, `/articles/revisions`, `/articles/moderation`, `/schools/public-policy` implement approval/audiences. School-only is default. Draft article revisions do not replace the visible approved revision. Only explicitly approved public content is accessible through `/public/*`; no indexing is enabled by default. Article text is untrusted plain text/Markdown, not trusted HTML. Future frontend must use escaped text or a vetted sanitized Markdown renderer.
10. `/accounts/force-logout`, `/accounts/deactivate`, `/support/metadata`, `/support/end`, `/integrity/events`, `/integrity/reviews`, `/notifications/read` provide attributed operational controls. Support returns only active/status/session-count metadata, not student content. Integrity events never impose automatic penalties.

POST `/imports/preview?classId=UUID`: raw XLSX, Idempotency-Key, CSRF. Template at GET `/imports/template`. Preview persists validated rows without creating Auth users. POST `/imports/confirm`: jobId and up to 300 selected integer row numbers. Each response processes at most five new identities (existing identities do not consume that batch budget), returns `outcomes`, per-response `created/reused/failed` counts, `remainingRows` and `complete`. Continue with the returned remaining rows until complete; failed rows are retried explicitly. Aggregate counts across responses rather than treating one response as the entire workbook. Same batch retries resume reservations and never reset existing passwords. Formula/external-link/macro/encrypted/oversized workbooks fail closed. Provisioning spans separate Auth/database steps; an activated Auth user with a lost response is reconciled on retry and cannot redisplay a password. Scheduled reconciliation retries activation of reserved Auth identities; unknown/missing identities require an explicit authorized retry.

POST `/files/upload?postId=UUID` or `?messageId=UUID`: raw binary, X-Filename, Content-Type, CSRF. Returns attachment ID/quarantined. No download is allowed until an approved scanner reports clean with a matching checksum. GET `/files/{id}` rechecks current parent access and streams from private R2 as an attachment. Upload completion before link publication is enforced by clean-state reads; scheduled reconciliation enqueues an uploaded object whose completion was lost, or releases an abandoned reservation after 24 hours.

Timestamps are UTC ISO 8601 with offsets; school timezone defaults Asia/Kolkata. Dates/periods are explicit. Snapshot versions and revision fields are optimistic concurrency controls. No custom frontend, dashboards, CSS or HTML is delivered.

A successful self-password change sets a fresh Secure HttpOnly session cookie and returns a fresh CSRF token under `data.csrfToken`; the internal cookie value is never returned as a JSON field. Use the new CSRF token for subsequent mutations. Staff reset instead returns the newly issued credential once, with all target sessions revoked.

Authentication provider throttling returns HTTP 429 / RATE_LIMITED with a bounded Retry-After header; it is not an invalid-password response. Network/provider unavailability returns 503 / AUTH_UNAVAILABLE. Supabase uses a token bucket with a burst of 30; setup for the 50-examinee pilot paces login, not answer-save/submission traffic. Guarded IP forwarding uses only Cloudflare CF-Connecting-IP with a modern server Secret key; arbitrary X-Forwarded-For is ignored. AUTH_IP_FORWARDING is enabled only after the Supabase dashboard setting is confirmed.

Run `npm run contracts:generate` after changing schemas and `npm run contracts:check` to detect stale OpenAPI without rewriting it. The generated specification targets OpenAPI 3.0 and is validated in automated tests.
