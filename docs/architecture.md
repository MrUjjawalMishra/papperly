# Papperly Version 1 backend architecture

One TypeScript Worker serves HTTP, Queue consumer, and scheduled entry points. Separate jobs deployment is unnecessary at this scale: queue work has independent invocation limits, bounded batch size, and does not run in answer-save requests. This does not establish mixed-load capacity; measure staging independently. PostgreSQL is the only authoritative application database. R2 is private binary storage. No D1, Firebase, Sites hosting, frontend assets, or API documentation UI exists.

The Worker maps school code and case-insensitive login ID to immutable UUID-based Supabase Auth aliases. Opaque cookie values are hashed in PostgreSQL; provider tokens are encrypted using AES-256-GCM under an environment-specific key. User requests use the user's Auth token against PostgREST, with RLS and explicit field projections. Account administration, session operations, and asynchronous jobs have separate service-only RPCs. Service credentials are never returned to clients. Disable Supabase public signup/anonymous login; configure alias domain and suppress email delivery before onboarding.

Ordinary authenticated roles have SELECT privileges only, filtered by RLS, and an explicit RPC allowlist. Protected schemas have both revoked privileges and default-deny RLS. SECURITY DEFINER functions have an empty search_path and fully qualified objects. Atomic database transitions include state changes, audit entries, notifications, and outbox creation. No claim is made of a transaction spanning Auth, PostgreSQL, R2, or Queues.

Exam publication snapshots content, protected keys, timing, and recipients. Marks use integer hundredths to avoid binary rounding. Saves lock the attempt, check server time, active writer, and next answer revision. Identical save retries return the acknowledged answer. Finalization locks the same row and records a stable receipt and durable grading jobs. Per-attempt display order stores stable question/option IDs; scoring never uses position. AI suggestions and teacher final marks are separate. Result publication stores an immutable revision snapshot and invalidates insight visibility transactionally.

Private group files inherit current group membership; query files inherit the private thread. API uploads validate types and sizes, reserve quota under a subscription row lock, write to private R2, and enqueue scanning. Files remain quarantined if upload/scanning is unavailable. Office expansion is bounded. A configured scanner must be an approved private service; there is no implicit provider or public scanning fallback.

Queries snapshot elapsed-hour policies. Extensions preserve original due dates and create notifications and history. Substantive solutions and student resolution are separate events. Clarification after an answer creates a response cycle. Reminders are deduplicated per cycle/deadline revision. Current group, directory, query, progress and report access checks restrict students during an active attempt. This cannot block external websites/devices or anonymous access to internet-public content.

All numeric progress is calculated by the server from published snapshots. No shared report cache is enabled: all HTTP responses use no-store and authorization is rechecked. Prepared CSV exports are actor-scoped, source-version checked, private, and expire after 24 hours. Public profile projections contain approved fields and safe activity counts only. Published articles retain their approved revision while a draft revision is reviewed. Public responses are no-store/noindex by default; audience revocation is checked on every read.

Queue messages contain IDs, not student answers. The database outbox owns retry state, lease recovery, attempt bounds, and run tokens. Consumers validate AI output, use idempotent quota reservations, and never replace reviewed marks. Gateway adapters have no selected provider by default. Provider timeouts/failures remain visible. Auth provisioning reserves immutable identity and quota, checks/creates an Auth UUID, then activates database records; retries never reset an existing identity. A lost one-time credential response requires an explicit reset.

See backend-requirements.md for gaps. Embedded PostgreSQL tests do not verify Supabase Auth configuration, PostgREST grants on a managed instance, actual Queue/R2 behavior, native concurrent database connections, backups, or regional latency.
