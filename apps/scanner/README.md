# Private ClamAV gateway

This is a Node 24 backend service, not a frontend. Cloudflare Workers cannot run the ClamAV daemon. Under the approved $0/month policy, deploy only to an existing free host; no paid host, container platform or plan upgrade is authorized. Compose is prepared, not a claim of a persistent live deployment.

The gateway accepts authenticated `POST /scan` octet-stream requests with `X-SHA256`. It checks the hash, caps the body at 10 MiB and limits concurrency to two requests. It communicates only through ClamAV INSTREAM, never daemon-visible filenames. The daemon has no public port in Compose. The HTTP gateway binds to host loopback; an existing HTTPS reverse proxy or approved free tunnel must expose only the authenticated gateway, never port 3310. Generate at least 32 unpredictable characters for SCANNER_API_KEY through the host's secure secret mechanism; save the matching Worker key in the Cloudflare GitHub environment. Do not put credentials in Compose, source, chat or logs.

Run `docker compose -f apps/scanner/compose.yml up -d --build` on the verified host with the gateway secret available in its environment. Docker must already be installed and the host must have sufficient free CPU/RAM/disk; the daemon is bounded to 2 GiB/two CPUs, gateway to 256 MiB/one CPU. Definitions persist in a Docker volume and Freshclam updates them. Gateway health requires a current loaded database and an actual clean scan. Startup/update lag remains unavailable; do not weaken the 48-hour signature-age check. SelfCheck reloads changed definitions every 60 seconds. Inspect service health and run the scripted clean/EICAR/limit checks after setup, update or restart.

Pinned images: ClamAV 1.5.4 and Node 24 with recorded image digests in Compose/Dockerfile. Upgrade through reviewed changes and rerun the corpus. Encrypted files, unsupported ZIP variants, invalid CRC/size metadata, excessive nesting, oversized expanded entries and exceeded scan limits fail closed. ZIP members are verified with bounded decompression independently of ClamAV heuristics: 20 MiB per expanded member, 50 MiB total, 1,000 entries and nesting depth 12. Archives themselves remain prohibited as app upload types; this parser protects office documents that use ZIP containers. No scanned bytes or filenames are logged or retained by the gateway.

Verification: `node scripts/verify-clamav.mjs` requires a real local ClamAV daemon on loopback CLAMD_PORT (default 33310). It starts a temporary authenticated gateway and uses synthetic clean bytes and the harmless EICAR test, including an archive and expansion-limit case. It records only status/verdict/engine metadata to work/clamav-verification.json. Unit tests also cover checksum/authentication denial, partial replies, stale signatures, errors and falsified archive metadata.

A successful local daemon test does not establish a live Worker → hosted gateway → daemon integration. Staging files stay quarantined until SCANNER_ENDPOINT and SCANNER_API_KEY are configured and that full path passes. Unavailability never means clean.

Provider references: [ClamAV scanning](https://docs.clamav.net/manual/Usage/Scanning.html), [INSTREAM protocol](https://docs.clamav.net/manual/Usage/ClamdProtocol.html), [official 1.5.4 release](https://github.com/Cisco-Talos/clamav/releases/tag/clamav-1.5.4). No public file-scanning service receives school documents.
